# 05 — 恢复手册

出问题时的自救流程。

---

## 一、症状速查

| 症状 | 处理 |
|---|---|
| **开机黑屏** | 确认显示器输入源 = HDMI 再重启（开机无 EDID 会退回 4K framebuffer） |
| **无限重启** | 从 U 盘 EFI 启动 → 关闭最近加入的 kext / 还原 config → 重启 |
| **WindowServer 反复崩溃** | `sudo touch /Users/Shared/gpu/phxboot-off` 后重启 |
| **GPU 异常 / 想禁用 GPU** | 同上 |
| **显示花屏 / 撕裂** | 检查 `debug.phxfb_dbuf=1`、`nvrm610.conf` 三键是否在位 |
| **SSH 连不上** | 用 `<hostname>.local` 重新解析（Wi-Fi/有线切换会换 IP） |
| **蓝牙消失** | 确认四个 kext 都在、`BlueToolFixup` 在 `IntelBluetoothFirmware` 之前 |
| **Wi-Fi 连不上** | 看日志 `security=`：WPA3-only 不支持，路由器改 WPA2/混合 |
| **桌面没背景 / 全黑** | 先确认壁纸没被改成纯黑图 |

## 二、紧急开关

### 2.1 关闭 GPU 接管（最常用）

```sh
sudo touch /Users/Shared/gpu/phxboot-off
sudo reboot
```

下次启动 `phxboot.sh` 会看到：

```
kill switch present: nothing to do
```

系统退回固件帧缓冲（画面正常，但桌面走 CPU 合成，较卡）。

**恢复**：

```sh
sudo rm -f /Users/Shared/gpu/phxboot-off
sudo reboot
```

### 2.2 强制重新 arming

如果 `PhxAMDFB on the panel: 0` 但你想让它接管：

```sh
sudo touch /Users/Shared/gpu/phxboot-m2
sudo chown root:wheel /Users/Shared/gpu/phxboot-m2
sudo nvram phxfb-boot=1
sudo nvram IONVRAM-FORCESYNCNOW-PROPERTY=phxfb
sudo reboot
```

**注意**：`phxboot-m2` 会被 `m2_fail` 自动删除。
如果反复失败，说明配置有问题，先查日志。

### 2.3 清除挂起标记

如果启动时看到 `previous attempt did not finish`：

```sh
sudo rm -f /var/db/phxboot.pending
```

## 三、从 U 盘救援

**前提**：有一个可启动的 U 盘 EFI（备份）。

1. 插入 U 盘
2. 开机按 F7/F11 选启动设备，或进 BIOS 改启动顺序
3. 从 U 盘 EFI 启动进入 macOS
4. 挂载内置盘 EFI 修复：

```sh
sudo diskutil mount disk0s1
# 修复 config.plist
sudo cp /Volumes/EFI/EFI/OC/config.plist.bak /Volumes/EFI/EFI/OC/config.plist
# 或移除有问题的 kext
sudo rm -rf /Volumes/EFI/EFI/OC/Kexts/XXX.kext
sudo reboot
```

## 四、回滚 GPU 驱动

### 4.1 回滚 PhxAccel（系统侧）

```sh
sudo diskutil mount disk0s1
# 备份在 /Users/Shared/gpu/backup/PhxAccel.kext.orig
sudo rm -rf /Library/Extensions/PhxAccel.kext
sudo cp -R /Users/Shared/gpu/backup/PhxAccel.kext.orig /Library/Extensions/PhxAccel.kext
sudo chown -R root:wheel /Library/Extensions/PhxAccel.kext
sudo chmod -R go-w /Library/Extensions/PhxAccel.kext
sudo BK=/Users/Shared/gpu/backup /Users/Shared/gpu/kinst.sh
sudo reboot
```

### 4.2 回滚 PhxBringup（EFI 侧）

```sh
sudo diskutil mount disk0s1
sudo rm -rf /Volumes/EFI/EFI/OC/Kexts/PhxBringup.kext
sudo cp -R /Users/Shared/gpu/backup/PhxBringup.kext.orig /Volumes/EFI/EFI/OC/Kexts/PhxBringup.kext
sudo chown -R root:wheel /Volumes/EFI/EFI/OC/Kexts/PhxBringup.kext
sudo reboot
```

### 4.3 回滚 AuxKC

```sh
# 列出备份
ls -la /Users/Shared/gpu/backup/aux.kc.*
# 恢复某个
sudo cp /Users/Shared/gpu/backup/aux.kc.20261123-235119 /Library/KernelCollections/AuxiliaryKernelExtensions.kc
sudo reboot
```

## 五、重建内核缓存

改过 `/Library/Extensions` 后必须重建 AuxKC：

```sh
sudo BK=/Users/Shared/gpu/backup /Users/Shared/gpu/kinst.sh
```

正常输出：

```
kmutil rc=0
  auxiliary kext
  Extension Information:
  ...
  com.luuumi.PhxAccel 0.1
aux KC published (old one, if any: /Users/Shared/gpu/backup/aux.kc.2026...)
```

**如果报错**，看 `/tmp/phx-kmuil.log`。

## 六、恢复 EFI 的完整步骤

如果 EFI 分区被写坏（例如误写大文件）：

```sh
# 1. 挂载
sudo diskutil mount disk0s1

# 2. 检查结构
ls /Volumes/EFI/EFI/
# 应该有 BOOT/ 和 OC/

# 3. 从备份恢复（备份在移动硬盘或本地）
sudo rm -rf /Volumes/EFI/EFI
sudo ditto /path/to/EFI-backup/EFI /Volumes/EFI/EFI

# 4. 验证
plutil -lint /Volumes/EFI/EFI/OC/config.plist
ls /Volumes/EFI/EFI/OC/Kexts/
```

## 七、诊断命令集

### 7.1 GPU 状态

```sh
# 接管状态
tail -20 /var/log/phxboot.log

# 关键指标
sysctl debug.phxfb_dbuf debug.phxfb_dbuf_state debug.phxfb_timing \
       debug.nvaccel_surface_gpu_on debug.nvaccel_iop_ok

# 显示信息
system_profiler SPDisplaysDataType

# PhxAMDFB 是否在 IORegistry
ioreg -rc PhxAMDFB -d1 | grep -E "PhxFBWidth|PhxFBHeight"

# 固件版本
ioreg -l -w0 -c PhxBringup | grep -E "phx-build|phx-fb-size"
```

### 7.2 内核日志

```sh
# PhxFB 相关
log show --predicate 'process == "kernel"' --last 10m | grep -iE "PhxFB|PhxAMDFB|NMXAccel"

# 崩溃报告
ls -lt /Library/Logs/DiagnosticReports/WindowServer-*.ips | head -5
```

### 7.3 权限检查（最容易忘的一项）

```sh
ls -la /System/Library/CoreServices/CoreTypes.bundle/Contents/Library/PhxGPU/NVMTLDriver.bundle/Contents/MacOS/
# 应该是 -rwxr-xr-x，不是 -rwx------
```

**如果不对**：

```sh
sudo chmod -R 755 /System/Library/CoreServices/CoreTypes.bundle/Contents/Library/PhxGPU
```

### 7.4 蓝牙 / Wi-Fi

```sh
# Wi-Fi
system_profiler SPAirPortDataType
kmutil showloaded | grep -i itlwm

# 蓝牙
system_profiler SPBluetoothDataType
ioreg -l -w0 -rc IOUSBHostDevice | grep -A5 "Bluetooth USB Host"
log show --predicate 'process == "bluetoothd"' --last 5m | grep -iE "transport|BlueTool"
```

## 八、什么时候该放弃

以下情况说明硬件或驱动生态有根本问题，继续折腾收益很低：

1. **`PhxAMDFB` 完全无法接管**（`panel: 0` 且加了 `phxboot-m2` 也没用）
   → 检查 `nvram phxfb-boot`、`PhxBringup` 是否加载、`phx-build` 版本

2. **接管后 GPU hang 无法恢复**
   → 用 `phxboot-off` 退回固件帧缓冲

3. **上游明确不支持你的硬件形态**
   → 例如：本项目需要 7 处修改才能让迷你主机工作，
      如果换一台没有内建屏且接口不同的机器，可能需要更多修改

4. **投入产出比太低**
   → 如果需要「日常主力机」而非「实验平台」，
      建议用 Intel 平台 + 受支持的 AMD 独显（RX 6600/6800 系列）

## 九、备份清单

**建议随时保留以下备份**：

```
EFI 分区完整备份（U 盘一份）
/Users/Shared/gpu/backup/
  ├── PhxAccel.kext.orig          原始版本
  ├── PhxBringup.kext.orig        原始版本
  └── aux.kc.*                    内核缓存备份
config.plist 的历史版本
```

**每次改动前先备份**：

```sh
sudo cp /Volumes/EFI/EFI/OC/config.plist \
        /Users/Shared/gpu/backup/config.plist.$(date +%Y%m%d-%H%M%S)
```
