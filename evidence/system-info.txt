
```
Intel(R) I226 V:
  Bus:            PCI
  Vendor ID:      0x8086
  Device ID:      0x125c

  PCIe Link:      5.0 GT/s, x1

  BSD Device:     en0 / en1
  MAC:            c8:ff:bf:03:d1:5c (en0)
                  c8:ff:bf:03:d1:5d (en1)
```

`ioreg` 里的驱动实例：

```
+-o AppleIGC  <class AppleIGC, registered, matched, active>
      "Model"          = "Intel(R) Ethernet Controller I226-V (IGC)"
      "IOMACAddress"   = <c8ffbf03d15c>
      "IOLinkStatus"   = 3                     (Up|Active)
      "IOLinkSpeed"    = 2500000000            (2.5 Gbps)
      "IOActiveMedium" = "00500036"            (IFM_2500_T, FDX|FLOW)
      "IOProbeScore"   = 4000                  (> 原生 dext 的 3000，自动抢占)
```

**为什么不用 macOS 原生的 `AppleEthernetE1000`**：
原生驱动在本机能绑定成功、能读出 MAC、能列出全部速率能力，
但 PHY 链路协商不出来（`media: autoselect (none)` / `status: inactive`），
换口、强制降速、重启驱动都无效。详见 [docs/03-踩坑记录.md](../docs/03-踩坑记录.md) 3.1。

**为什么用 v1.8 而不是 v1.9**：
v1.9 的 PR #38 让驱动监听 MSI 中断源，但 `pci_enable_msi_block()` 被 `#if 0` 禁用、
MSI 从未真正启用 → 中断永不触发 → **RX 完全死掉**
（link 显示 active 但 `Ipkts` 恒为 0）。详见 [docs/03](../docs/03-踩坑记录.md) 3.1。
